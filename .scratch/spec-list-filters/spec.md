# Фильтры списка позиций: статус, поставщик, «черновики»

Статус: реализовано. `tsc --noEmit` и `eslint` чисто; новые тесты (14 + 8) зелёные (в песочнице vitest падает на `spawn EPERM` при загрузке конфига, прогон сделан с расширенным доступом).

## Что просили

На странице проекта со спецификацией добавить фильтры по статусу, по подрядчику и «Черновик», собрать их в панель «Все фильтры» и держать состояние в URL SearchParams.

## Решения

1. **«Подрядчик» — это компания-поставщик позиции** (`SpecItem.companyName`). Значение фильтра — снапшот имени, а не `companyId`: у позиции, чей поставщик удалён из справочника, id уже `null`, а имя осталось — по id такая позиция выпадала бы из фильтра молча. Параметр в URL — `company`, подпись поля — «Поставщик»: так этот же контрагент назван в карточке позиции и в форме. Слово «подрядчик» в приложении уже занято компанией-исполнителем услуги (`service_operations.contractor_company_id`), второй синоним в интерфейсе не заводим.
2. **«Черновик» — переключатель «Только черновики»**, а не отдельное измерение: это псевдоним статуса `draft` (в интерфейсе — «Не выбрано»), и в URL он живёт как `status=draft`. Так у одного измерения один источник правды: отдельный `draft=1` мог бы оказаться в URL рядом с `status=picked`, и список был бы пуст при двух «включённых» фильтрах. Галочка в шторке и чип в тулбаре — быстрый доступ к тому же значению, что видно и в селекте статусов (приём уже есть в баннере «требуют замены»: «Показать их» выставляет `status=replace`).
3. **Панель.** На узких экранах — нижняя шторка «Все фильтры» (категория, статус, поставщик, черновики, сортировка). На широких — те же контролы прямо в тулбаре, как в библиотеке материалов: шторка там не рендерится. Подписи, счётчики и разбор значений из URL живут в `layout/spec-filter-controls.tsx`, поэтому разметок две, а правила одни.
4. **Состояние — в URL SearchParams**: `q`, `type`, `status`, `company`, `sort`. Фильтрация идёт по уже загруженному массиву позиций через `history.replaceState`, без похода на сервер (как было).
5. **Выборка и сортировка вынесены из хука** в `lib/spec/list-filters.ts`: это единственное место, где решается, что видит пользователь, и его можно проверить тестами без рендера. Заодно там же счётчики для контролов (`specTypeCounts`, `specStatusCounts`, `specSupplierOptions`, `countDrafts`).
6. **Поставщик, которого больше нет в позициях, остаётся в списке вариантов** — иначе значение фильтра из URL не видно и нечем снять (то же правило у производителя в библиотеке материалов). Пустой список поставщиков объясняет причину подписью «Поставщики не указаны».
7. **Чипсы активных фильтров** на узких экранах показывают и поставщика: сводка должна отвечать, почему список пуст, не открывая шторку.

## Известное рядом (не в этой правке)

Фильтры живут в URL через `history.replaceState`, то есть без серверного рендера. Ссылки на диалоги (`?dialog=add`, «Закупка», «Сводка», «Редактировать») строит серверная страница из своего снимка `searchParams` (`withSearchParams`), а он устаревает, как только пользователь поменял фильтр: при клике по такой ссылке параметры фильтров из URL пропадают, и список разворачивается целиком (в поле поиска при этом остаётся набранный текст — оно неконтролируемое). Это свойство появилось не сейчас: так же ведут себя `q`, `type`, `status` и `sort`. Лечится построением href в момент клика по живому `window.location.search`; отдельная правка.

## Открытый вопрос

Статус `draft` в приложении подписан «Не выбрано» (`SPEC_STATUS_CONFIG`), а в запросе и в макете (`temp/Specifications App.dc.html`) он называется «Черновик». Из-за этого переключатель говорит «Черновики», а селект и чипсы — «Не выбрано». Глобальное переименование задевает PDF, Excel, публичную спецификацию и подписи истории, поэтому без отдельного решения не делалось.
