# 06: Вид записи в «Дополнительно» и документы к оплате

**What to build:** Выбор вида записи (оплата/возврат) уезжает в раскрывающийся блок «Дополнительно», чтобы не стоять первым полем формы. К оплате можно прикрепить документ (чек, платёжное поручение): он виден в карточке оплаты и во вкладке «Файлы» позиции, скачивается и удаляется по тем же правам, что остальные файлы.

Детали — в `.scratch/material-payments/REPORT.md`; решения Q3/Q5/Q13 в приложении А; файловый слой — миграция `20260927_001` и `lib/spec/spec-item-files.ts`.

**Blocked by:** 05.

**Status:** ready-for-human

- [x] Вид записи доступен только из «Дополнительно»; по умолчанию оплата; подпись кнопки следует за видом при закрытом блоке
- [x] Возврат по-прежнему можно внести (возможность задачи 03 не теряется)
- [x] Миграция добавляет `spec_item_files.payment_id` с запретом каскадного удаления и проверкой, что файл и оплата — одной позиции одной организации
- [x] Загрузить документ к оплате можно из карточки оплаты; файл виден у оплаты и во вкладке «Файлы»
- [x] Документ скачивается и удаляется по существующим правам файлов (`record:create`); `viewer` видит, но не пишет
- [x] Чужой `payment_id` (другая позиция, другая организация, удалённая оплата) отвергается с понятным текстом
- [x] Тесты: ядро (принадлежность оплаты позиции, чужой `payment_id`), действие, вкладка

## Comments

### Итог реализации (2026-10-11)

**Вид документа расширен по решению человека.** Тикет по умолчанию оставлял одну
категорию `document`; вместо этого `SPEC_ITEM_FILE_CATEGORIES` и CHECK-констрейнт
расширены видами: `document | invoice | receipt | contract | specification |
drawing | texture | other`. `document` оставлен значением по умолчанию (и
запасным для строк, записанных в обход формы), `other` и `texture` не тронуты.
Подписи — в `FILE_CATEGORY_OPTIONS` (`lib/spec/file-view.ts`); расхождение списка
кода и CHECK-констрейнта ловит `file-content.test.ts` (читает обе миграции).

**Миграция** — `supabase/migrations/20261011_001_add_payment_files.sql`:

1. `spec_item_files.payment_id uuid` + FK на `spec_item_payments (id)`
   `on delete restrict` (ADR 0004) + частичный индекс
   `where payment_id is not null and deleted_at is null`;
2. триггер `spec_item_files_payment_scope` — сверяет позицию, организацию и
   проект файла со строкой оплаты, а при расхождении (чужая позиция, чужая
   организация, чужой проект, отменённая оплата) **снимает ссылку**, а не падает:
   ошибка запретила бы и мягкое удаление испорченного документа. Составной FK
   здесь не работает — `payment_id` nullable, и `MATCH SIMPLE` пропускает строку
   с `NULL` в любой колонке, а принадлежность организации он не выражает вовсе;
3. снятие и пересоздание `spec_item_files_category_check` с новым списком.

**Ядро** (`lib/spec/spec-item-files.ts`): `paymentId` во входе загрузки,
`paymentId` + `payment: { kind, paidAt }` в записи файла. `resolvePayment` читает
строку оплаты запросом с условиями `org_id + spec_item_id + project_id +
deleted_at is null` — чужой идентификатор просто не находится, и на все
расхождения один понятный текст. Список файлов достраивает подписи одним
дополнительным запросом пачкой (`decorateWithPayments`); его ошибка список не
ломает. `deleteSpecItemFile` и `getSpecItemFileUrl` тоже возвращают запись с
подписью — иначе клиент, обновивший строку ответом, терял бы связь.

**UI:** кнопка «Прикрепить документ» у каждой оплаты (право `record:create`, как
у файлов, — не «автор или администратор»), список документов под записью с
открытием и удалением; вкладка «Файлы» показывает у документа к оплате подпись
«К оплате от <дата>». Диалог загрузки один на оба пути — отличается пропсом
`paymentId`.

**Документ к отменённой оплате не теряется.** Отмена оплаты ссылку не рвёт
(решение тикета), поэтому такой файл виден во вкладке «Файлы» с подписью
«К отменённой оплате» — красной, потому что это состояние, а не справка, — и
удаляется оттуда же. Без этого документ был бы достижим только из карточки
живой оплаты, которой уже нет, а `payment_id` в его строке вёл бы в никуда молча.
Подпись ставит сервер (`SpecItemFilePaymentInfo.cancelled`): список читает и
отменённые оплаты. Прикрепить документ к отменённой оплате ядро по-прежнему
отказывается — отказ тот же и с тем же текстом, что у чужого `payment_id`.

**Отменённые проверки по ревью:** сбой чтения оплаты больше не выдаётся за
«оплата не найдена» (`FAILED`, «Не удалось проверить оплату» — повтор имеет
смысл), удаление и подпись ссылки на файл больше не читают оплату лишним
запросом, тест синхронизации категорий сравнивает сам список из CHECK, а не
вхождение строки в текст миграций, глоссарий пополнен видами документов.

**Что осталось открытым:** миграция в живую БД **не применена** — токен
`supabase login` в этом окружении без права `database_write` (`migration list` →
403). Применение: `npx supabase db push`, затем `npm run db:types` (типы в
`lib/supabase/database.types.ts` уже обновлены вручную: `payment_id` и
`spec_item_files_payment_id_fkey`).

### Решения (интервью 2026-10-10)

1. **Возврат не убираем.** Список видов прячется в «Дополнительно», но вход
   остаётся: иначе возможность, сделанную задачей 03, стало бы нечем
   воспользоваться. Подпись кнопки отправки следует за видом, поэтому выбранный
   возврат виден и при закрытом блоке.
2. **Документ виден в двух местах:** у оплаты и во вкладке «Файлы». Один файл,
   две точки входа — не копия.
3. **Категория — `document`.** Новую категорию не заводим: список
   `document | texture | other` продублирован в CHECK и закреплён тестом, а
   расширять его ради чека незачем.
4. **Отмена оплаты документ не удаляет.** Файл остаётся в истории позиции: смысл
   вложения именно в том, чтобы пережить ошибочную запись.

### Открытые вопросы

1. **Показывать ли во вкладке «Файлы», что файл — чек конкретной оплаты?** По
   умолчанию нет: файл остаётся обычным документом позиции, а связь видна только
   у оплаты. Пометка — отдельное решение, +1 поле в выборке.
2. **Предел числа документов на оплату** не задаём: у файлов уже есть лимит
   размера и типа, а количество ограничено здравым смыслом. Если понадобится —
   отдельное решение.
3. **Что показывать при удалении оплаты, у которой есть документы,** — сейчас
   ничего: оплата мягко скрывается, документ остаётся видимым во вкладке
   «Файлы». Возможно, стоит пометить такие файлы как «к отменённой оплате».
