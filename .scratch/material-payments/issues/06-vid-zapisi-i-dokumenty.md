# 06: Вид записи в «Дополнительно» и документы к оплате

**What to build:** Выбор вида записи (оплата/возврат) уезжает в раскрывающийся блок «Дополнительно», чтобы не стоять первым полем формы. К оплате можно прикрепить документ (чек, платёжное поручение): он виден в карточке оплаты и во вкладке «Файлы» позиции, скачивается и удаляется по тем же правам, что остальные файлы.

Детали — в `.scratch/material-payments/REPORT.md`; решения Q3/Q5/Q13 в приложении А; файловый слой — миграция `20260927_001` и `lib/spec/spec-item-files.ts`.

**Blocked by:** 05.

**Status:** ready-for-agent

- [ ] Вид записи доступен только из «Дополнительно»; по умолчанию оплата; подпись кнопки следует за видом при закрытом блоке
- [ ] Возврат по-прежнему можно внести (возможность задачи 03 не теряется)
- [ ] Миграция добавляет `spec_item_files.payment_id` с запретом каскадного удаления и проверкой, что файл и оплата — одной позиции одной организации
- [ ] Загрузить документ к оплате можно из карточки оплаты; файл виден у оплаты и во вкладке «Файлы»
- [ ] Документ скачивается и удаляется по существующим правам файлов (`record:create`); `viewer` видит, но не пишет
- [ ] Чужой `payment_id` (другая позиция, другая организация, удалённая оплата) отвергается с понятным текстом
- [ ] Тесты: ядро (принадлежность оплаты позиции, чужой `payment_id`), действие, вкладка

## Comments

### Решения (интервью 2026-10-10)

1. **Возврат не убираем.** Список видов прячется в «Дополнительно», но вход
   остаётся: иначе возможность, сделанную задачей 03, стало бы нечем
   воспользоваться. Подпись кнопки отправки следует за видом, поэтому выбранный
   возврат виден и при закрытом блоке.
2. **Документ виден в двух местах:** у оплаты и во вкладке «Файлы». Один файл,
   две точки входа — не копия.
3. **Категория — `document`.** Новую категорию не заводим: список
   `document | texture | other` продублирован в CHECK и закреплён тестом, а
   расширять его ради чека незачем.
4. **Отмена оплаты документ не удаляет.** Файл остаётся в истории позиции: смысл
   вложения именно в том, чтобы пережить ошибочную запись.

### Что уже готово

Вид записи в «Дополнительно» сделан в задаче 05 (последним коммитом):
`payment-form.tsx` оборачивает поле в `<details><summary>Дополнительно</summary>`,
плюс тест «вид записи спрятан в „Дополнительно", но остаётся доступным».
Остаётся проверка прогоном.

### План по документам

| Шаг | Что делать |
| --- | --- |
| Миграция | `spec_item_files.payment_id uuid null` + FK на `spec_item_payments` **без каскада** (ADR [0004](../../../docs/adr/0004-finansovaya-istoriya-ne-udlyaetsya-kaskadom.md) — финансовая история не удаляется каскадом) |
| Проверка принадлежности | Триггером, как `payment_sync_scope`: он проверяет, что оплата той же позиции и организации, и перезаписывает `payment_id` в `null`, если не совпало. **Составной FK здесь не работает:** `payment_id` nullable, а `MATCH SIMPLE` пропускает строку с `NULL` в любой колонке — то есть `(NULL, spec_item_id)` не проверится. Прецедент триггерной проверки — `20261009_001` |
| Ядро | `SpecItemFileEntry.paymentId`; `UploadSpecItemFileInput.paymentId?`; проверка, что оплата активна и принадлежит позиции |
| Действие | `uploadSpecItemFile` принимает `paymentId` из `FormData` |
| UI у оплаты | В карточке факта — список документов, «Прикрепить», скачивание, удаление по правам |
| UI во вкладке «Файлы» | Показывать существующее; при желании — пометка «чек к оплате от <дата>» (+1 поле в выборке) |
| Тесты | Ядро: чужой `payment_id`, удалённая оплата, `null` разрешён. Действие: права. Вкладка: файл виден у оплаты |

### Открытые вопросы

1. **Показывать ли во вкладке «Файлы», что файл — чек конкретной оплаты?** По
   умолчанию нет: файл остаётся обычным документом позиции, а связь видна только
   у оплаты. Пометка — отдельное решение, +1 поле в выборке.
2. **Предел числа документов на оплату** не задаём: у файлов уже есть лимит
   размера и типа, а количество ограничено здравым смыслом. Если понадобится —
   отдельное решение.
3. **Что показывать при удалении оплаты, у которой есть документы,** — сейчас
   ничего: оплата мягко скрывается, документ остаётся видимым во вкладке
   «Файлы». Возможно, стоит пометить такие файлы как «к отменённой оплате».
